# 拘束・関節技のノウハウ（実測メモ）

拘束まわりの姿勢・カメラ・入口を作るときに、実際に試して分かったことの記録。
**関節技（ArmLock）は 2026-11-06 に見送り**にした。再挑戦するときはここから読む。

## 1. 関節技を見送った理由

3種類の形を作り直したが、どれも「関節技」に見えなかった。

| 試した形 | 結果 |
|---|---|
| 正面から手首を取って肘を折る | 「手首を握っているだけ」に見える |
| コブラツイスト（横に並んで上体を折る） | 背骨の横曲げ（`torsoRoll`）が弱く、頭が落ちて前髪で顔が隠れる |
| ハンマーロック（背後から前腕を背中へ） | 前腕が背中に回らず、胸の前で曲がる |

**本当の原因は最後に分かった**: `EnemyBrain.IsPinning` を関節技で立てていなかったため、
見た目側（`PinHoldPose`）が**腕のIKもカメラも一切動かしていなかった**。
つまり上の3つは「腕を組む処理が走っていない状態」を見ていた。

→ もし再挑戦するなら、**最初に `IsPinning` を立てる**（`TryArmLock` 内）。
この1行で、手が彼女の腕に乗り、カメラも寄るようになる（見送り直前に確認済み）。

## 2. 彼女の腕は「方向ベクトル」では前腕が動かない

`CharacterAnimator` の `armRUpper` / `armRFore` は方向ベクトルだが、**前腕は値に反応しない**（実測）。

- `armRFore` を **±X / ±Y / ±Z の6方向**に振っても、見た目が変わらなかった
- `armRUpper`（上腕）は効く（腕が下がる）
- `+Z = 前`、`+Y = 上`、`-X = 彼女の右` は `StanceArmRUpper` / `StanceArmRFore` から確認できる

**対策**: 前腕を狙った位置に置きたいときは、敵の腕と同じく
`ProceduralRig.SolveTwoBone(右上腕, 右肘, 右手首, 目標, pole)` で **IK** する。
方向ベクトルで前腕を組もうとすると、時間だけ溶ける。

## 3. 演出カメラは `HoldFocus` を使う（`Push` 系は薄まる）

- `PushDistance(0.28, 0.12)` を毎フレーム呼んでも、**実効 0.37〜0.46** までしか寄らず、フレームで変動する
  （減衰前提のAPIなので、`TickEffects` が先に減衰させてから使う）
- `HoldFocus(0.28, pivot, x, 0.5f, pitch, yaw)` なら **実効 0.33** で安定
- 秒数は `0.5`（腹パンと同じ）。`0.12` にすると寄りが薄まる

## 4. 関節技以外で入れた改善（押さえつけ）

- 制限時間 4.2 秒。掴んで 1.1 秒は押さえたまま（脱出の猶予）、そこから 0.55 秒間隔で膝 5 発
- クールダウン 2.5 秒。準備ができた押さえ役は**彼女の正面へ回り込む**（`TryApproachForPin`）
- 手は**両前腕**を掴む（片手を空けると「掴んでいない手」が浮いて見えた）
- 拘束されている間は**ずっと腹パンと同じ寄りのカメラ**（距離 0.28 / ピボット +0.05 / 俯角 2° / ヨー −32° / 正面へ 0.30m ずらす）

## 5. 検証用の入口

| 操作 | 内容 |
|---|---|
| **P キー** | いちばん近い敵に押さえつけを指示（`-pinnow` で起動 1.5 秒後に 1 回） |
| **O キー** | 関節技を指示（見送りに伴い、実装ごと削除） |
| `-pinburst=<prefix>` | 拘束開始から 0.05 秒ごとに 80 枚（4 秒ぶん）を撮る |
| `-handoffburst=<prefix>` | 引き渡しが起きた瞬間から 0.05 秒ごとに 40 枚（2 秒ぶん）を撮る（1 回だけ） |
| `-handoffkind=pin` / `-handoffkind=back` | 引き渡しの抽選を固定する（撮り比べ用。既定は 50:50） |

`PinHotkey` は「すでに掴まれている」と失敗するので、**0.6 秒おきに再試行**する実装にしてある。

## 6. 再挑戦するときの順番

1. `TryArmLock` で `IsPinning = true`
2. 彼女の腕は **IK**（`SolveTwoBone`）で「肩甲骨の間」へ。方向ベクトルは使わない
3. 彼の手も IK（手首・肘の2点）
4. カメラは `HoldFocus(0.28, +0.05, x, 0.5f, 2, -32)` から始めて撮り比べ
5. 形が決まってから、ダメージ（0.8 秒ごとに腕 −3）と HUD を載せる

## 7. 引き渡し（たらい回し）で分かったこと

3 体で戦っているとき、拘束している敵が彼女を別の敵へ渡す。抜けても次に捕まるので「数で押される」圧力が出る。

### 7.1 姿勢の追加は必ず `ApplyPose()` の**後**に書く

`CharacterAnimator.ApplyPose()` は状態ごとに全ボーンを組み直すので、
**メソッドの前に足した姿勢は毎フレーム上書きされて消える**（今回これで 2 回空振りした）。

```csharp
ApplyPose();

// ここに書く（Grapple.PushPulse など）
if (Grapple != null && Grapple.PushPulse > 0f && Rig.Ready)
{
    float p = Mathf.Clamp01(Grapple.PushPulse);
    Rig.Chest.localRotation *= Quaternion.Euler(20f * p, 0f, 0f);
    Rig.LUpperArm.localRotation *= Quaternion.Euler(45f * p, 0f, 0f);
    ...
}
```

`ApplyPose()` の呼び出しは 3 か所ある（`Bind()` 直後 / `LateUpdate` の終わり / ポーズ撮影用）。
**実行時に効くのは `LateUpdate` の 1 か所**なので、そこに足す。

### 7.2 押し出したら掴み位置へ寄せ直す

`PlayerMotor.Knockback(0.9m, 0.3s)` だけで終わると、相手との距離が開いたまま拘束が始まり
**「2 人目の拘束が遠い」**になる（実測）。押し出し＋向き変更のあとに `SnapToCaptor(next, kind)` で
掴み位置ぴったりに寄せる（実装は `PlayerGrapple.Shove`）。

### 7.3 3 者が動くと「突き飛ばし」に見える

| 対象 | 動き | 実装 |
|---|---|---|
| 押す側 | 両腕を前へ突き出す 0.22 秒 | `EnemyBrain.PushAway()` / `IsPushing` → `EnemyFigure` が腕を組む |
| 彼女 | 上体 +20°、腕を後ろへ 45°、顔だけ起こす 0.35 秒 | `PlayerGrapple.PushPulse` |
| 受け取る側 | 両腕を開いて胸の高さに構え、半歩かがんで受け止める（0.9 秒） | `EnemyBrain.BeginCatch()` / `IsCatching` → `EnemyFigure` が構えを組む |
| 彼女の足 | 押されている間、左右交互に踏み直す（たたらを踏む） | `ApplyPose()` 内、`SolveLeg` の**前**で `footL` / `footR` をずらす |

押す側が棒立ちのままだと、**彼女が自分から 2 人目へ歩いて行った＝「2 人目が掴みに来た」**に見える（ユーザー評）。
押す側の腕だけで印象が変わる。

### 7.5 足は `ApplyPose()` の**中**、`SolveLeg` の前で動かす

腕は `ApplyPose()` の後に足せば効くが、**足は効かない**（同じ理由で上書きされる）。
足先は `footL` / `footR`（キャラクター基準のローカル座標）を書き換え、
その後の `Rig.SolveLeg(..., transform.TransformPoint(footR), pole)` に拾わせる。

```csharp
// ApplyPose() 内、Rig.OffsetHips より前（＝ SolveLeg より前）
float t = 1f - Mathf.Clamp01(Grapple.PushPulse);   // 0 → 1
float dirZ = Grapple.Kind == GrappleKind.Back ? 1f : -1f;   // 押される向きの逆へ足が残る
footL += new Vector3(0.02f, 0.07f * stepL, dirZ * (0.10f * drag + 0.05f * stepL));
footPitchL = Mathf.Max(footPitchL, 18f * stepL);   // 踏み直す足はつま先立ち
```

- 押される向きは**正面（Pin）は前、背面（Back）は後ろ**。足はその逆へ残る
- `footPitch` を上げると、かかとが浮いて「踏ん張っている」に見える
- 腰（`hipsOffset.y`）も少し落とすと重さが出る

### 7.4 抽選と派生

- タッグパンチを 5 発食らい切り、腹ダメージが上限未満なら、カメラが通常に戻って 1 秒後に 1 度だけ抽選する
  （`GrappleHandOff.TryChain`、既定 70%）。外れたら元の敵が拘束を続ける
- 押さえつけ（Pin）は時間制限つきの短い技なので対象外
- 正面（`Pin`）: そのまま押さえつけ → 膝蹴り 5 発まで続く（`TakeOverHold` が `IsPinning` を立てる）
- 背面（`Back`）: 羽交い締め → 条件を満たせばタッグ腹パン
- 抽選比は 50:50（`GrappleHandOff` 内）。腹パンを見せたいなら背面寄りにする
- 渡す側（元の拘束者）は `LockForHandOff(0.9)` で `Recover` 固定、受け手は `TakeOverHold` で固定する。
  この間は AI も `KeepSpacing` も動かさない
- **ベアハッグ**（`BearHug`）は正面 0.80〜1.30m から全員が出せる。押さえつけと 50:50 で選び、
  `BearHugPose` が両腕を彼女の背中へ回す。0.9 秒後から 1 秒ごとに HP −2 の締め付け。
  締め付けは `PlayerGrapple.Squeeze()` で体を引き寄せ、0.54m → 0.38m まで詰めて胸が触れる距離まで密着させる。
  引き寄せは `PullPulse` が中盤で最大になり、彼女の上体が先に持っていかれて
  頭・腕・足が遅れて残る（`CharacterAnimator`）。敵も体重を後ろへ預けて腕を引き込む。
  密着した瞬間（`IsBearHugContact`）だけ HP −2 が入り、0.10 秒保ってから 0.30 秒かけて離す。
  これを 0.65 秒周期で繰り返す（引き寄せ 0.10 秒）。密着中は `SqueezePulse` で体が内側へ潰れ、
  拘束中は `LiftPulse` が上がり、腰が浮いて両足が床から離れる（ぶら下がる）。
  彼女は腕を体側に封じられ、もがくと肘が開く（`CharacterAnimator` の `State.Grabbed`）
- タッグ腹パンの相方は **2.5m 以内**から選び、0.1〜0.3 秒かけて位置へ歩かせる（瞬間移動しない）
- 彼女は 0.9m 突き飛ばしてから戻すのではなく、**掴み位置まで一続きに移動**する
  （`0.12 + 距離 × 0.18` 秒、0.18〜0.65 秒）。向きは移動中に 0.25 秒で変える。
  押し終わりの `SnapToCaptor` は無い（行き過ぎて戻る動きがワープに見えたため）

## 8. 壁押さえつけ（2026-11実装）

レーンの外（+Z）に壁を置き、その前で正面の押さえつけが成立したときだけ壁へ押し出す。
掴み方（`GrappleKind.Pin`）・もがき 12 回・制限時間・膝蹴り 5 発は通常の押さえつけと同じ。

### 8.1 レーン固定を一時的に外す

- `PlayerMotor.LateUpdate` は毎フレーム `position.z = _laneZ` に固定する。
  壁へ出す間だけ `HasLaneZOverride` / `LaneZOverride` で差し替える。
- `EnemyBrain.LateUpdate` も `position.z = Target.position.z` に固定するので、
  `IsWallPinning` の間は自前の位置（`_wallToPos`）を使う。
- 押し出しは 0.18 秒、戻りは 0.25 秒。**瞬間移動させない**。
  戻りは `PlayerGrapple` が `PlayerMotor` の上書きを 0 へ補間し、
  `EnemyBrain` は `_wallReturn` でレーンへ戻る。
- 他の敵は壁押さえつけ中、レーン（z=0）に留める。全員が彼女の z に付いてくると壁へめり込む。

#### 戻りの穴（2026-11 修正）

3 つあり、いずれも「位置は戻るのに見た目が付いてこない／戻らない」形で出た。

| 症状 | 原因 | 直し方 |
|---|---|---|
| 位置は壁から抜けるのに、立ち姿のまま横滑りする | 壁の反りが `State.Grabbed` の中でしか掛かっていなかった。`EndWallPin` は `IsWallPin=false` にするので、戻り補間（0.25 秒）の間は `PoseIdle`（反りなし）になる | `ApplyWallBrace` を切り出し、`State.Grabbed` **以外**でも `WallPinWeight` で掛ける（倒れ姿勢は除外）。重みの減衰も 0.2 秒固定から戻りと同じ `WallExitSeconds` に揃えた |
| 引き渡し（`HandOff`）で壁際の z が残る | 戻り補間の入口が `!_wallExitRemaining && !IsGrappled` だった。引き渡しは掴まれたままなので一度も走らない | 条件から `!IsGrappled` を外す。即座に寄せる経路（`shove: false`）だけ `ClearWallExit()` で打ち切る（`SnapToCaptor` の位置と競合するため） |
| レーンが 0 以外のときに壁際から別の z へ滑る | 戻り先を `0` に決め打ちしていた（`_wallExitFromZ * SmoothStep(...)`） | 戻り先を `PlayerMotor.LaneZ`（本来のレーン）へ。`Mathf.Lerp(lane, _wallExitFromZ, ...)` で抜く |

判定は **姿勢の実測**で行う。`WallPinWeight` だけを見るテストは、重みが減衰していれば
姿勢が立ち姿に戻っていても通ってしまう（実測: 修正を外しても通った）。
`WallPinRuntimeTests.壁から戻るあいだ姿勢が立ち姿へ先に戻らない` は腰の高さを
「壁中 / 戻り途中 / 戻りきった後」の 3 点で測り、途中が立ち姿勢の高さへ戻っていないことを見る。

### 8.2 向きと距離

- 彼女は壁に背を向け、**-Z（室内側）**を向く。押さえ役はその手前（+Z 側ではなく -Z 側）に立つ。
- 距離は 0.72m（カプセル半径 0.30 + 0.40 の 0.70 に余裕）。
- 壁の表面 `FaceZ` は 1.78。彼女の中心は `FaceZ - 0.46`（頭と後ろ髪の表面ぶん離す。§8.2b）。

### 8.2b 壁を貫通させない（実測で直した）

最初の実装は彼女が壁を突き抜けていた。原因は 3 つで、**骨ではなく描画メッシュで測る**まで気づけなかった。

| 症状（実測） | 原因 | 直し方 |
|---|---|---|
| 頭が +0.044m、髪が +0.154m（108 本中 43 本）壁の内側 | 上体を **-20°** 反らせ、腰を壁の表面に付けていた | 反りを -7° に、頭は +6°（うつむき）へ。立ち位置を壁から 0.46m 離す（`TryWallPin` の `playerRadius`） |
| 骨は全部手前（-0.10m）なのに `Hair` メッシュだけ +0.004m | **スプリングボーンは壁を知らない**。ジョイントは手前でも毛束の面が外へ張り出す | `VrmHairWallClamp`（実行順 **26000**）でジョイントを壁の 0.10m 手前へ押し戻す |
| 押し戻しても数 mm 残る | クランプを **12000**（姿勢の適用 20000 より前）に置いていた。頭を回した時点で髪が壁へ入り直す | 実行順を 26000（`CharacterAnimator` の後）へ |

**判定は必ず描画メッシュで行う**（`-walllog` の `[WallMesh]`、PlayMode の `壁押さえつけ中に体と髪が壁を貫通しない`）。
骨だけ見ると「貫通していない」と誤判定する。

```
[WallClear] face=1.78 head=-0.105 ... hairOver=0/108
[WallMesh] maxZ-face=-0.056 (OK)
```

- 壁の入口: `TryPin` の中で `WallPinSites.Find` が壁を返したときだけ `TryWallPin` へ。
- **ベアハッグは壁の前で選ばない**（`CanStartWallPin`）。同じ正面の掴みの抽選でベアハッグが先に選ばれると、
  壁際で正面から掴まれても壁へ押し出されない（実測: PlayMode テストで Pin が選ばれなかった）。
- 彼女は壁に**背中を向け**（-Z を向く）、押さえ役はその手前に立つ。

### 8.3 姿勢とカメラ

- 彼女: 通常の押さえつけは前へ折れるが、壁では**上体を反らせる**（`TorsoPitch -3`）。
  **壁ポーズは膝蹴りより先に適用する**。後に置くと膝で折れた上体を反りが打ち消す。
- 彼女の両手首は、拘束（`WallStage.Held`）に入ってから 0.40 秒かけて**壁の表面へ貼り付く**
  （`PlayerGrapple.WallAdhereWeight` → `CharacterAnimator.SolveOverheadArms`）。
  手首は world 固定（足元 +1.62m）で、体がもがいて揺れても壁から浮かない。
  掌は壁へ向け、指は開く（掴む相手がいない）。
- 押さえ役は**彼女の前腕を掴んだまま**にする。手首は壁の上まで上がり彼の腕では届かないので、
  掴み所を手首から前腕（肘寄り）へ滑らせる。そのため立つ位置を `captorGap=0.38`（従来 0.55）へ寄せた。
  0.55 のままだと手が 0.3m 届かず、彼女の胸の前で止まって「腹を掴んでいる」ように見えた（実測）。
- 押さえ役: 上体を起こしたまま体重を前へ預ける（`IsWallPinning` で `torsoPitch +9` / `hipsZ +0.06`）。
- カメラ: レーンのままだと壁が奥に隠れる。`PinHoldPose` が `RequestCinematicShot` で
  部屋側（z ≈ -1.2）から斜めに固定し、膝蹴りで少し寄る。

### 8.4 壁の置き場所

- `WallPinSite` を付けたオブジェクトが壁。無ければ `WallPinProps` が実行時に 4 か所作る
  （x=-6 / 4 / 14 / 24、`FaceZ=1.78`、幅 2.6m、高さ 2.18m）。
- 壁の描画は通常は地面の下。掴み後にせり上がり、解除後に地面へ戻る。投げと拘束の段階は `PlayerGrapple.WallPhase` が管理する。
- 当たり判定は付けない。投げ先は `PlayerGrapple.BeginWallPin` が決める。
- ジオメトリ側で置くときは `-nowallprops` で自動生成を止める。
- 確認: `-wallpintest`（`-pinshot=` / `-pinburst=` 併用可）または `-wallpinnow`。
